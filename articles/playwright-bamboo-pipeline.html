Objective: Automated Validation After QA DeploymentObjectif : Valider automatiquement après chaque déploiement QA

The goal is to show how to use Playwright as an automatic control after a QA deployment, while keeping a testing strategy simple, progressive and maintainable. L'objectif est de montrer comment utiliser Playwright comme contrôle automatique après un déploiement QA, tout en gardant une stratégie de tests simple, progressive et maintenable.

Key skills:Compétences illustrées : Playwright · TypeScript · Bamboo · Git · CI/CD · Test Strategy

1. Pipeline Objective1. Objectif du pipeline

The principle is to automatically validate that an application deployed in the QA environment remains usable. After deployment, Bamboo runs a Playwright smoke test. If the test fails, the deployment is considered a failure. Le principe est de valider automatiquement qu'une application déployée en environnement QA reste utilisable. Après le déploiement, Bamboo exécute un test de fumée Playwright. Si ce test échoue, le déploiement est considéré comme en échec.

General FlowFlux général

Git → Bamboo Build → QA Deployment → Playwright Test → Verdict

This approach places the automated test as close as possible to deployment. It allows rapid detection of a critical regression, such as inability to log into the application. Cette approche place le test automatisé au plus près du déploiement. Elle permet de détecter rapidement une régression critique, par exemple l'impossibilité de se connecter à l'application.

Architectural PrinciplePrincipe d'architecture

  • The application is deployed on the QA environment.L'application est déployée sur l'environnement QA.
  • Node.js and Playwright run on the Bamboo agent, not on the application VM.Node.js et Playwright s'exécutent sur l'agent Bamboo, pas sur la VM applicative.
  • The agent must be able to reach the QA application over HTTPS.L'agent doit pouvoir joindre l'application QA en HTTPS.
  • A single smoke test is enough to validate the mechanism before expanding coverage.Un premier test de fumée suffit pour valider le mécanisme avant d'élargir la couverture.

2. Recommended Test Organization2. Organisation recommandée des tests

A clear structure separates test levels and reusable code. Unit tests remain with the application code; Playwright is used for tests that control the deployed application. Une structure claire sépare les niveaux de tests et le code réutilisable. Les tests unitaires restent avec le code applicatif ; Playwright est utilisé pour les tests qui pilotent l'application déployée.

3. Tags and Execution Strategy3. Tags et stratégie d'exécution

Regression and re-test don't require separate folders. They can be selected with tags while keeping each scenario in its test level. La régression et le re-test ne nécessitent pas de dossiers séparés. Ils peuvent être sélectionnés avec des tags tout en conservant chaque scénario dans son niveau de test.

TagTag UsageUsage CommandCommande
@smoke Vital functionsFonctions vitales npx playwright test --grep @smoke
@regression Non-regression suiteSuite de non-régression npx playwright test --grep @regression
@confirmation Re-test a fixed anomalyRe-test d'une anomalie corrigée npx playwright test --grep @confirmation
💡 Key PointPoint clé

For a deployment pipeline, the @smoke suite must remain short and stable. Longer suites can be executed at night or before a release. Pour un pipeline de déploiement, la suite @smoke doit rester courte et stable. Les suites plus longues peuvent être exécutées la nuit ou avant une release.

4. Integrating Playwright into Bamboo4. Intégration Playwright dans Bamboo

The build publishes the Playwright project as an artifact. The QA deployment retrieves this artifact, installs necessary dependencies, then runs the test. Le build publie le projet Playwright comme artifact. Le déploiement QA récupère cet artifact, installe les dépendances nécessaires puis exécute le test.

Essential StepsÉtapes essentielles

  • Publish the Playwright folder as a build artifact.Publier le dossier Playwright comme artifact du build.
  • Download the artifact in the QA deployment.Télécharger l'artifact dans le déploiement QA.
  • Set necessary variables to target the QA environment.Positionner les variables nécessaires pour viser l'environnement QA.
  • Install dependencies with npm ci.Installer les dépendances avec npm ci.
  • Install Chromium if the agent doesn't already have it.Installer Chromium si l'agent ne le possède pas déjà.
  • Run the Playwright test.Exécuter le test Playwright.
  • Fail the deployment if the test fails.Faire échouer le déploiement si le test échoue.

Example CommandExemple de commande

npx playwright test LoginLogout.spec.ts --no-deps --project=chromium

In this case, --no-deps avoids setup/cleanup projects that require a REST API not yet available in the environment. --project=chromium limits execution to the necessary browser in the pipeline. Dans ce cas, --no-deps permet d'éviter les projets de setup/cleanup qui nécessitent une API REST non encore disponible. --project=chromium limite l'exécution au navigateur nécessaire dans le pipeline.

5. Example Smoke Test: Login/Logout5. Exemple de smoke test : connexion / déconnexion

A Login/Logout test is a good first deployment control: it verifies that the application responds, authentication works, and the user can end their session. Un test Login/Logout est un bon premier contrôle de déploiement : il vérifie que l'application répond, que l'authentification fonctionne et que l'utilisateur peut terminer sa session. 

test('Login then logout @smoke', async ({ page }) => {
    await page.goto(process.env.APP_URL!);

    // Authentication
    await page.getByRole('textbox', { name: "Username" })
        .fill(process.env.TEST_USERNAME!);
    await page.getByRole('textbox', { name: 'Password' })
        .fill(process.env.TEST_PASSWORD!);
    await page.getByRole('button', { name: 'Login' }).click();

    // Wait for dashboard
    await page.waitForLoadState('networkidle');
    
    // Verify logged in
    await expect(page).toHaveTitle(/Dashboard/);
    
    // Logout
    await page.getByRole('button', { name: 'Logout' }).click();
    
    // Verify redirected to login
    await expect(page).toHaveTitle(/Login/);
});
🔒 Security NoteNote de sécurité

Internal URLs, accounts, passwords and other infrastructure information must remain externalized in environment variables or in the CI/CD secret manager. Les URL internes, comptes, mots de passe et autres informations d'infrastructure doivent rester externalisés dans des variables d'environnement ou dans le gestionnaire de secrets du CI/CD.

6. Local Validation Before Pipeline6. Validation locale avant le pipeline

A test destined for Bamboo should first be validated locally with a command as close as possible to the one in the pipeline. Un test destiné à Bamboo doit d'abord être validé localement avec une commande aussi proche que possible de celle du pipeline.

The expected result for the smoke test is simple: the scenario passes before the modification is pushed to Git and integrated into the pipeline. Le résultat attendu pour le smoke test est simple : le scénario passe avant que la modification soit poussée dans Git et intégrée au pipeline.

8. Progressive Pipeline Evolution8. Évolution progressive du pipeline

Automation can be enhanced progressively. The goal is not to run all tests after each deployment, but to place the right level of control at the right time. L'automatisation peut être enrichie progressivement. L'objectif n'est pas d'exécuter tous les tests après chaque déploiement, mais de placer le bon niveau de contrôle au bon moment.

StepÉtape FocusAxe EvolutionÉvolution

2 ResultsRésultats Publish results with a JUnit reporter in Bamboo.Publier les résultats avec un reporter JUnit dans Bamboo.
3 SecuritySécurité Move secrets to secure Bamboo variables.Déplacer les secrets vers des variables Bamboo sécurisées.
4 IntegrationIntégration Enable necessary services and reintroduce API setups.Activer les services nécessaires et réintroduire les setups API.
5 RegressionRégression Create a scheduled night run for @regression.Créer une exécution planifiée de nuit pour @regression.
6 TraceabilityTraçabilité Link results to a test management tool, e.g. Zephyr Scale.Relier les résultats à l'outil de gestion des tests, par exemple Zephyr Scale.

9. Key Takeaways9. Points clés à retenir

  • Playwright can serve as a safety net immediately after a QA deployment.Playwright peut servir de garde-fou immédiatement après un déploiement QA.
  • The smoke test must be fast:Le smoke test doit être rapide : it validates essential functions, not all regressions.il valide les fonctions essentielles, pas toute la régression.
  • Separating smoke / integration / system / acceptance makes maintenance easier.La séparation smoke / intégration / système / acceptation facilite la maintenance.
  • The pipeline must reproduce execution already validated locally.Le pipeline doit reproduire une exécution déjà validée localement.
  • Secrets and environment parameters must be externalized.Les secrets et paramètres d'environnement doivent être externalisés.
  • Coverage expands progressively:La couverture s'élargit progressivement : smoke → results → API → regression → traceability.smoke → résultats → API → régression → traçabilité.

ConclusionConclusion

This integration illustrates a CI/CD-oriented QA approach: start with a simple and useful control, make it reliable, then progressively expand coverage. The result is a pipeline capable of detecting a critical regression quickly while maintaining reasonable deployment times. Cette intégration illustre une démarche QA orientée CI/CD : commencer par un contrôle simple et utile, le rendre fiable, puis enrichir progressivement la couverture. Le résultat est un pipeline capable de détecter rapidement une régression critique tout en conservant des temps de déploiement raisonnables.

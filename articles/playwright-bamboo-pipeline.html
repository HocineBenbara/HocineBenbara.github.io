Running Playwright Tests in a Bamboo Pipeline Intégrer des tests Playwright dans un pipeline Bamboo

How to use Playwright as an automatic gate right after a QA deployment — while keeping the test strategy simple, progressive and maintainable. Utiliser Playwright comme contrôle automatique juste après un déploiement QA — tout en gardant une stratégie de tests simple, progressive et maintenable.

Playwright TypeScript Bamboo CI/CD Git Smoke tests

The goal of the pipelineObjectif du pipeline

The idea is to automatically confirm that an application deployed to the QA environment is still usable. Once the deployment finishes, Bamboo runs a Playwright smoke test. If that test fails, the deployment is marked as failed. Le principe est de valider automatiquement qu'une application déployée en environnement QA reste utilisable. Après le déploiement, Bamboo exécute un test de fumée Playwright. Si ce test échoue, le déploiement est considéré comme en échec.

This puts the automated check as close to the deployment as possible, so a critical regression — for example, users no longer being able to log in — is caught within minutes. Cette approche place le test automatisé au plus près du déploiement. Elle permet de détecter rapidement une régression critique, par exemple l'impossibilité de se connecter à l'application.

Architecture principlesPrincipe d'architecture

  • 🚀
    The application is deployed to the QA environment.L'application est déployée sur l'environnement QA.
  • 🤖
    Node.js and Playwright run on the Bamboo agent, not on the application VM.Node.js et Playwright s'exécutent sur l'agent Bamboo, pas sur la VM applicative.
  • 🔒
    The agent must be able to reach the QA application over HTTPS.L'agent doit pouvoir joindre l'application QA en HTTPS.
  • ✅
    A single smoke test is enough to validate the mechanism before widening coverage.Un premier test de fumée suffit pour valider le mécanisme avant d'élargir la couverture.

Organizing the testsOrganisation des tests

A clear structure separates test levels from reusable code. Unit tests stay with the application code; Playwright drives the deployed application. Une structure claire sépare les niveaux de tests et le code réutilisable. Les tests unitaires restent avec le code applicatif ; Playwright pilote l'application déployée.

Tags and execution strategyTags et stratégie d'exécution

Regression and re-testing don't need their own folders. They are selected with tags, while each scenario stays in its own test level. La régression et le re-test ne nécessitent pas de dossiers séparés. Ils sont sélectionnés avec des tags, tout en conservant chaque scénario dans son niveau de test.

Tag UsageUsage CommandCommande
@smokeVital functionsFonctions vitalesnpx playwright test --grep @smoke
@regressionRegression suiteSuite de non-régressionnpx playwright test --grep @regression
@confirmationRe-test a fixed defectRe-test d'une anomalie corrigéenpx playwright test --grep @confirmation

💡 In a deployment pipeline, the @smoke suite must stay short and stable. Longer suites belong in a nightly run or a pre-release run. 💡 Dans un pipeline de déploiement, la suite @smoke doit rester courte et stable. Les suites plus longues s'exécutent la nuit ou avant une release.

Wiring Playwright into BambooIntégration Playwright dans Bamboo

The build publishes the Playwright project as an artifact. The QA deployment fetches it, installs what it needs and runs the test. Le build publie le projet Playwright comme artifact. Le déploiement QA récupère cet artifact, installe les dépendances nécessaires puis exécute le test.

  • 1
    Publish the Playwright folder as a build artifact.Publier le dossier Playwright comme artifact du build.
  • 2
    Download the artifact in the QA deployment.Télécharger l'artifact dans le déploiement QA.
  • 3
    Set the variables that point to the QA environment.Positionner les variables qui visent l'environnement QA.
  • 4
    Install dependencies with npm ci.Installer les dépendances avec npm ci.
  • 5
    Install Chromium if the agent doesn't already have it.Installer Chromium si l'agent ne le possède pas déjà.
  • 6
    Run the Playwright test.Exécuter le test Playwright.
  • 7
    Fail the deployment if the test fails.Faire échouer le déploiement si le test échoue.
bamboo · script task 
npx playwright test LoginLogout.spec.ts --no-deps --project=chromium

In this case, --no-deps skips the setup/cleanup projects that rely on a REST API not yet available in the environment, and --project=chromium limits the run to the only browser the pipeline needs. Dans le cas étudié, --no-deps évite les projets de setup/cleanup qui nécessitent une API REST non encore disponible sur l'environnement, et --project=chromium limite l'exécution au seul navigateur nécessaire dans le pipeline.

Smoke test example: login / logoutExemple de smoke test : connexion / déconnexion

A login/logout test is a great first deployment check: it proves the application responds, authentication works and the user can end their session. Un test Login/Logout est un bon premier contrôle de déploiement : il vérifie que l'application répond, que l'authentification fonctionne et que l'utilisateur peut terminer sa session.

tests/01-smoke/LoginLogout.spec.ts 
test('Login puis logout @smoke', async ({ page }) => {
  await page.goto(process.env.APP_URL!);

  // Authentication
  await page.getByRole('textbox', { name: "Nom d'utilisateur" })
    .fill(process.env.TEST_USERNAME!);
  await page.getByRole('textbox', { name: 'Mot de passe' })
    .fill(process.env.TEST_PASSWORD!);
  await page.getByRole('button', { name: 'Connexion' }).click();

  // Post-login assertions and logout...
});

🔐 Internal URLs, accounts, passwords and other infrastructure details must stay out of the code — in environment variables or the CI/CD secrets manager. 🔐 Les URL internes, comptes, mots de passe et autres informations d'infrastructure doivent rester externalisés dans des variables d'environnement ou dans le gestionnaire de secrets du CI/CD.

Validate locally firstValidation locale avant le pipeline

A test meant for Bamboo should first pass locally, with a command as close as possible to the pipeline's. Un test destiné à Bamboo doit d'abord être validé localement, avec une commande aussi proche que possible de celle du pipeline.

terminal 
$ npm ci
$ npx playwright install chromium
$ npx playwright test LoginLogout.spec.ts --no-deps --project=chromium

The expected result is simple: the scenario passes before the change is pushed to Git and picked up by the pipeline. Le résultat attendu est simple : le scénario passe avant que la modification soit poussée dans Git et intégrée au pipeline.

Best practicesBonnes pratiques

  • ⚡
    Keep smoke tests short, independent and reliable.Garder les smoke tests courts, indépendants et fiables.
  • 🏷️
    Use accessible selectors — role, label or data-testid — rather than fragile CSS classes.Utiliser des sélecteurs accessibles — rôle, libellé ou data-testid — plutôt que des classes CSS fragiles.
  • 🧹
    Never commit node_modules, Playwright reports or test results.Ne pas commiter node_modules, les rapports Playwright ou les résultats d'exécution.
  • 🔐
    Never expose passwords in the repository or the logs.Ne pas exposer de mots de passe dans le dépôt ou les logs.
  • 📦
    Use npm ci in the pipeline to rebuild dependencies from package-lock.json.Utiliser npm ci dans le pipeline afin de reconstruire les dépendances depuis package-lock.json.
  • 🎲
    Fix or remove a flaky test that would needlessly block deployments.Corriger ou retirer du pipeline un test flaky qui bloquerait inutilement les déploiements.
  • 🗂️
    Create and clean up each scenario's own data whenever possible.Créer et nettoyer les données propres à chaque scénario lorsque c'est possible.

Growing the pipeline step by stepÉvolution progressive du pipeline

The goal isn't to run every test after every deployment, but to put the right level of control at the right moment. L'objectif n'est pas d'exécuter tous les tests après chaque déploiement, mais de placer le bon niveau de contrôle au bon moment.

2ResultsRésultatsPublish results in Bamboo with a JUnit reporter.Publier les résultats avec un reporter JUnit dans Bamboo.
3SecuritySécuritéMove secrets to secured Bamboo variables.Déplacer les secrets vers des variables Bamboo sécurisées.
4IntegrationIntégrationEnable the required services and bring back the API setups.Activer les services nécessaires et réintroduire les setups API.
5RegressionRégressionAdd a scheduled nightly run for @regression.Créer une exécution planifiée de nuit pour @regression.
6TraceabilityTraçabilitéLink results to the test management tool, e.g. Zephyr Scale.Relier les résultats à l'outil de gestion des tests, par exemple Zephyr Scale.

Key takeawaysPoints clés à retenir

  • 🛡️
    Playwright can act as a safety net immediately after a QA deployment.Playwright peut servir de garde-fou immédiatement après un déploiement QA.
  • ⏱️
    The smoke test must be fast: it checks the essentials, not the whole regression.Le smoke test doit être rapide : il valide les fonctions essentielles, pas toute la régression.
  • 🧱
    Separating smoke / integration / system / acceptance makes maintenance easier.La séparation smoke / intégration / système / acceptation facilite la maintenance.
  • 💻
    The pipeline should replay a run already validated locally.Le pipeline doit reproduire une exécution déjà validée localement.
  • 🔐
    Secrets and environment settings must be externalized.Les secrets et paramètres d'environnement doivent être externalisés.
  • 📈
    Coverage grows progressively: smoke → results → API → regression → traceability.La couverture s'élargit progressivement : smoke → résultats → API → régression → traçabilité.

This integration reflects a CI/CD-oriented QA approach: start with a simple, useful check, make it reliable, then widen coverage step by step. The result is a pipeline that catches critical regressions fast while keeping deployment times reasonable. Cette intégration illustre une démarche QA orientée CI/CD : commencer par un contrôle simple et utile, le rendre fiable, puis enrichir progressivement la couverture. Le résultat est un pipeline capable de détecter rapidement une régression critique tout en conservant des temps de déploiement raisonnables.
